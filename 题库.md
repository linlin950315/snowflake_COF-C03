## Q3　`S2-27`　Snowflake CLI 变量模板语法

A user is automating a data pipeline using the Snowflake CLI and needs to pass variables into SQL scripts.
Which variable templating syntaxes should be used? (Choose two.)
- A. STANDARD
- B. LEGACY
- C. JINJA
- D. NONE
- E. ALL

<details><summary>答案</summary>

**BC**　⚠️ 社区投票 AB/AC/BC 各 33%，答案有争议。

**笔记（对照官方文档 `snow sql --enable-templating`）：**
- 本题问的是：Snowflake CLI 传变量到 SQL 脚本时，SQL 里的**占位符**可以用哪几种写法（模板语法）。对应关系：
  - STANDARD：占位符写成 `<% var %>` 默认启用，官方推荐
  - LEGACY：占位符写成 `&var` / `&{ var }`，沿用 SnowSQL，默认启用，但已弃用
  - JINJA：占位符写成 `{{ var }}`，也是合法语法，但**默认不启用**，需手动加 `--enable-templating JINJA`
- NONE：关闭模板；ALL：一次启用所有语法（二者是开关，不是语法）
- 重点：`<% 变量名 %>` 会在执行前被替换成 `-D` 传入的值。
- 按"默认启用"理解选 AB；按"合法语法"理解 JINJA 也成立。社区投票 AB / AC / BC 各约三分之一，考试以题库答案 BC 记

</details>

## Q17　`S2-27`　CLI 连接配置优先级（环境变量 > config.toml）

A user adds a new connection called [dev_project] to their config.toml file, which includes setting role = DEVELOPER.
Then the user runs this command: snowsql -c dev_project. When they run SELECT current_role(); inside the session, the query returns SYSADMIN.
Why did Snowflake CLI use the SYSADMIN role?
- A. SYSADMIN is the Engineer's default role and cannot be overridden by the config.toml file.
- B. The [dev_project] connection in the config.toml file was missing a warehouse parameter, which caused the CLI to ignore the role parameter.
- C. A SNOWFLAKE_ROLE environment variable was set to SYSADMIN, which takes precedence over the config.toml file.
- D. The config.toml file is used if the connection is also passed as a command-line flag, such as snowsql --role DEVELOPER.

<details><summary>答案</summary>

**C**

**笔记：**
- 连接参数优先级从高到低：**命令行参数（command-line arguments / flags，如 `--role`）> 环境变量（environment variables，如 `SNOWFLAKE_ROLE`）> config.toml（配置文件）**。
- 本题：环境变量 `SNOWFLAKE_ROLE=SYSADMIN` takes precedence over config.toml 里的 `role = DEVELOPER`，所以 `current_role()` 返回 SYSADMIN。
- 判断依据：选项 C 原文写明 "SNOWFLAKE_ROLE environment variable"；环境变量一般全大写加下划线，config.toml 里是小写键值对（`role = DEVELOPER`）。
- 优先级中"命令行参数最高"是按 Snowflake CLI 通常行为补充，题库未直接考；本题答案以 C 为准。
- 题干写 `snowsql -c` 但用 config.toml，疑似出题时混用两个工具（config.toml 是 Snowflake CLI 的格式）。

</details>

## Q62　`S2-26`　Dynamic Table 全量刷新原因

A Developer has scheduled a dynamic table to refresh incrementally, but the process uses a full refresh instead.
When used, which query operator will cause a full refresh instead of the scheduled incremental refresh?
- A. DISTINCT
- B. GROUP BY
- C. LATERAL JOIN
- D. UNION ALL

<details><summary>答案</summary>

**C**　社区投票 C 67% / A 33%。

**解析**（依据官方 [Supported queries](https://docs.snowflake.com/en/user-guide/dynamic-tables/supported-queries) 支持矩阵）：
- A DISTINCT：去重，增量支持。
- B GROUP BY：增量支持（仅 `ROLLUP` / `CUBE` / `GROUPING SETS` 不支持）。
- **C 普通 LATERAL JOIN：增量不支持 → 全量刷新**。但 `LATERAL FLATTEN` 支持增量（不能选 `SEQ` 列）。
- D UNION ALL：上下拼在一起,不去重。两边的列数和类型要兼容。UNION(不带 ALL)会去重,也支持增量。增量支持。
- 其他会全量刷新的：`EXCEPT` / `INTERSECT` / `MINUS`、UDTF。
- `AUTO` 遇到不支持的构造会退回 FULL；显式 `INCREMENTAL` 则建表报错。

**LATERAL JOIN 是什么**：对左表每一行执行一次右边子查询，右边可引用左边当前行的列（如“每个客户最近 2 笔订单”）。
- 推测原因（官方未说明）：上游一行变化后，右边子查询要重新执行，难以判断哪些输出行受影响。

</details>

A company has multiple business units that need data isolation but shared administrative oversight.
Which solution will meet this requirement?
- A. Create separate Snowflake accounts for each business unit.
- B. Create a single database with separate schemas for each business unit.
- C. Create separate databases within one account assigned to a business unit.
- D. Create separate virtual warehouses for each business unit and share databases and schemas.

<details><summary>答案</summary>

**A**　⚠️ 社区投票 A 50% / C 50%。

**解析：**
- **A 分账号**：账号是 Snowflake 最强的隔离边界（存储、计算、用户、角色、安全策略全部分开）。"shared administrative oversight" 由 **Organization（ORGADMIN / Organization Account）** 实现：多个账号挂在同一组织下，统一创建、监控账号，统一查看用量与账单。符合官方"业务单元/环境需隔离时，在一个组织下建多个账号"的推荐做法。
- **C 同账号分数据库**：只是靠 RBAC 的逻辑隔离；ACCOUNTADMIN 可见全部数据，用户、角色、网络策略等账号级对象共用，授权出错就会跨部门泄露，算不上真正的 data isolation。
- **B / D**：隔离更弱，D 只隔离了计算，没有隔离数据。
- 出题思路：data isolation → 账号级隔离；shared administrative oversight → Organization；合起来 = 一个组织下的多个账号。

</details>

## Q112　`S2-26`　Dynamic Table

Which object type creates a data object that collects information from two tables without implementing manual tracking of data dependencies
through transformations?
- A. Materialized view
- B. Stream
- C. Transient table
- D. Dynamic table

<details><summary>答案</summary>

**D**

**解析**：
- A Materialized view（物化视图）：看到“物化视图”就想到**单表限制**（不支持 JOIN），所以不能从两张表收集数据。
- B Stream：只记录表的变更（增删改），本身不是结果表，也不合并两张表。
- C Transient table（临时表）：一种表类型，没有 Fail-safe，Time Travel 最多 1 天，比永久表省存储费。它只是普通的存储表，数据要自己用 INSERT、MERGE 等写入，不会自动更新，也不跟踪依赖。
- D Dynamic table：动态表。写一条多表 JOIN 的查询，Snowflake 自动按依赖关系刷新，不用手动跟踪依赖，所以是答案。

</details>
